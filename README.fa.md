# رندوید (rndvid)

یک برنامهٔ ترمینالی برای انتخاب تصادفی یک فایل **ویدیو، کتاب یا صوت** از هر پوشه‌ای که انتخاب می‌کنید، و باز کردن آن با برنامهٔ پیش‌فرض سیستم.

[English](README.md) · **فارسی**

</div>

```
bun run src/index.ts
```

ابتدا می‌پرسد چه چیزی می‌خواهید انتخاب کنید، اجازه می‌دهد در همهٔ درایوها بگردید، و به تعداد دلخواه فایل‌های یکتا را انتخاب می‌کند که **یکی‌یکی** باز می‌شوند و برنامه منتظر می‌ماند تا قبلی بسته شود.

<div dir="rtl">

## پیش‌نیازها

Bun (یا Node 18 به بالا، چون فقط از کتابخانه‌های داخلی Node استفاده شده است). نیازی به `ffprobe`، `ffmpeg` یا هیچ ابزار جانبی دیگری نیست.

## اجرا

```
bun run src/index.ts [گزینه‌ها]
```

| گزینه | توضیح |
| --- | --- |
| `-f, --folder <مسیر>` | پوشهٔ کتابخانه. مرورگر پوشه را نادیده می‌گیرد. |
| `-n, --count <عدد>` | چند فایل انتخاب شود. پیش‌فرض: ۱ |
| `--mode <نام>` | `video`، `book` یا `audio`. منوی نوع رسانه را نادیده می‌گیرد. |
| `--max-depth <عدد>` | چند سطح پوشه پایین برود. پیش‌فرض: ۴. مقدار `0` یعنی بدون محدودیت. |
| `--size <بازه>` | فیلتر حجم. به پایین‌تر صفحه ببینید. |
| `--exclude-watched` | فایل‌هایی که قبلاً باز کرده‌اید را نادیده بگیر. |
| `--detach` | منتظر بسته شدن برنامه نمان. |
| `--library` | به‌جای انتخاب تصادفی، کل کتابخانه را ببین. |
| `--dry-run` | انتخاب‌ها را چاپ کند، بدون پرسیدن یا باز کردن چیزی. |
| `-h, --help` | راهنما. |

## حالت‌های رسانه

اولین چیزی که از شما پرسیده می‌شود این است که چه می‌خواهید انتخاب کنید. هر حالت فقط قالب‌های خودش را جست‌وجو می‌کند، بنابراین اسکن کتاب، همهٔ ویدیوهای درایو را با خود نمی‌آورد.

| حالت | قالب‌ها |
| --- | --- |
| `video` | mp4 mkv avi mov webm m4v ts wmv flv mpg mpeg ogv |
| `book` | epub pdf mobi azw azw3 fb2 djvu cbz cbr m4b m4a aac |
| `audio` | mp3 m4a m4b aac flac wav ogg opus wma aiff |

کتاب‌های صوتی (`.m4b`) عمداً هم در حالت `book` و هم در `audio` هستند. در هر حالتی که انتخاب کنید، فایل‌ها با برنامهٔ پیش‌فرض همان پسوند باز می‌شوند.

انتخاب شما به خاطر سپرده می‌شود، بنابراین این منو فقط بار اول یا وقتی خودتان با `m` آن را عوض کنید ظاهر می‌شود.

## بازگشت به آخرین پوشه

اگر پوشه‌ای را قبلاً تأیید کرده باشید، بار بعد چنین پرسیده می‌شود:

```
◆  Return to D:\Videos\Some Show?  (298 videos)
│  ❯ Yes
│    No, pick a folder
```

پاسخ شما هم به خاطر سپرده می‌شود: اگر بار قبل «بله» را انتخاب کرده باشید، دفعهٔ بعد بدون پرسش مستقیم همان‌جا باز می‌شود.

پوشه‌های اخیر با `R` در دسترس‌اند. پوشه‌هایی که پاک شده‌اند به‌صورت خودکار از فهرست حذف می‌شوند تا با مسیرهای شکسته روبه‌رو نشوید.

## نمای درختی

کلید `t` نمای درختی کتابخانه را باز می‌کند:

```
◆  Video library
│  filter none
│  ❯ ▾ library
│      ▾ Season 1  2
│        ✓ S01E01.mkv    700 MiB  22m
│        ○ S01E02.mkv    668 MiB
│      ▾ Season 2  13
│      ○ top.mp4         150 MiB
│
└  ↑↓ move · → expand · ← collapse · enter roll · / filter · esc cancel   1/8
```

- `↑` `↓` حرکت، `→` باز کردن، `←` بستن
- `Enter` انتخاب تصادفی از همان پوشه
- `/` جست‌وجو در درخت؛ مسیرهای والد نگه داشته می‌شوند تا مسیر خوانا بماند
- `✓` باز شده، `○` باز نشده، کنار فایل‌های باز شده مدت تماشا نمایش داده می‌شود

## میان‌برهای صفحه‌کلید

| کلید | کار |
| --- | --- |
| `1` `3` `5` | انتخاب ۱ / ۳ / ۵ فایل |
| `a` | انتخاب از کل کتابخانه |
| `t` | نمای درختی |
| `r` | فایل‌های اخیر |
| `R` | پوشه‌های اخیر |
| `f` | فیلتر حجم |
| `u` | برگرداندن آخرین انتخاب |
| `w` | روشن/خاموش کردن نادیده گرفتن فایل‌های دیده‌شده |
| `l` | نمای کتابخانه |
| `d` | تغییر پوشه |
| `m` | تغییر نوع رسانه |
| `?` | پنل راهنما |
| `q` | خروج |

`Enter` به‌عنوان پیش‌فرض «دوباره انتخاب کن» عمل می‌کند.

## فیلتر حجم

```
500mb        حداقل ۵۰۰ مگابایت
>1gb         همان، به شکل صریح
1gb-         حداقل ۱ گیگابایت
-800mb       حداکثر ۸۰۰ مگابایت
<800mb       همان، به شکل صریح
200mb-2gb    بین این دو
700-900      عدد بدون واحد یعنی مگابایت
```

واحدها: `b`، `kb`، `mb`، `gb`، `tb` (و `KiB`/`MiB`/`GiB`/`TiB`).

فیلتر مدت‌زمان یا کیفیت تصویر وجود ندارد، چون به `ffprobe` نیاز دارد و این برنامه عمداً چنین وابستگی‌ای نمی‌خواهد. فیلتر فقط بر اساس حجم فایل است.

## عمق اسکن

اسکن به‌صورت بازگشتی است اما به‌طور پیش‌فرض در ۴ سطح محدود شده. این کار بدترین حالت درایوها را کنار می‌گذارد و در عین حال به سریال‌های تودرتوی پوشه‌های دوره هم می‌رسد. وقتی محدودیت عمق اسکن را قطع کند، **اعلام می‌کند** و یک پوشهٔ حذف‌شده را نام می‌برد؛ هرگز بی‌صدا فایلی را از قلم نمی‌اندازد.

```
--max-depth 2    کم‌عمق: فقط پوشه‌های بلافاصله زیر ریشه
--max-depth 0    بدون محدودیت
```

پوشه‌های سیستمی (`Windows`، `WinSxS`، `Program Files`، `DriverStore` و…) در هر عمقی نادیده گرفته می‌شوند. پوشه‌هایی که خوانده نمی‌شوند گزارش و رد می‌شوند و هرگز باعث توقف نمی‌شوند.

## تاریخچهٔ تماشا

«قبلاً دیده شده» برای هر پوشه جدا نگهداری می‌شود و در `%APPDATA%\rndvid\history` ذخیره می‌گردد. هنگام **باز کردن** ثبت می‌شود، نه هنگام پایان؛ بنابراین اگر یک پخش‌کننده خراب باشد باز هم شمرده می‌شود و دوباره انتخاب نمی‌شود.

با کلید `u` می‌توانید آخرین انتخاب را برگردانید؛ فایل دوباره وارد فهرست می‌شود و اثر آن از تاریخچه پاک می‌گردد.

> **یک نکتهٔ صادقانه دربارهٔ «ادامه از همان‌جا»:** این برنامه مدت زمانی را که فایل باز بوده به‌صورت ساعت دیواری ثبت می‌کند و مثلاً می‌نویسد «۲۲ دقیقه». این فقط **تخمینی** از این است که چقدر جلو رفته‌اید، نه موقعیت واقعی پخش. هیچ راه استانداردی در ویندوز وجود ندارد که از پخش‌کننده بپرسد «کجایی؟» و به هر برنامه هم پرچم متفاوتی لازم است. اگر پخش‌کنندهٔ شما پشتیبانی می‌کند، می‌توانید در تنظیمات قالب آرگومان resume تعریف کنید (مثلاً `mpv --start={time}`)، ولی به‌صورت پیش‌فرض غیرفعال است.

## باز کردن فایل‌ها

ویندوز در `HKCR\.mp4` فقط یک ProgID ذخیره می‌کند؛ دستور اجرا زیر همان ProgID قرار دارد. بنابراین برنامه مسیر `HKCR\.ext` ← ProgID ← `shell\open\command` را طی می‌کند و سپس خودِ برنامه را اجرا می‌کند تا بتواند منتظر بسته شدنش بماند. `cmd /c start` فقط راه‌حل پشتیبان است، چون کار را به پوسته می‌سپارد و فوراً برمی‌گردد و در آن صورت «منتظر ماندن» بی‌معنا می‌شود.

مقادیر `REG_EXPAND_SZ` باز می‌شوند و هر دو جایگزین `%1` و `%L` پشتیبانی می‌شوند (Windows Media Player از دومی استفاده می‌کند).

## آزمون‌ها

```
bun run typecheck   # tsc با حالت سخت‌گیرانه
bun run test        # ۱۳۲ آزمون واحد
bun run test:e2e    # ۸۳ بررسی سرتاسری روی CLI واقعی
bun run check       # هر سه
```

آزمون‌های واحد منطق خالص را پوشش می‌دهند، از جمله آزمون کای‌دو برای مولد عدد تصادفی و محدودیت عمق روی درخت‌های ساختگی با عمق مشخص. مجموعهٔ سرتاسری، خودِ برنامه را با `--dry-run` روی یک fixture موقت اجرا می‌کند.

تعامل‌های صفحه‌کلید با تزریق جریان‌های ساختگی آزمون می‌شوند، چون اجرای آزمون با کلید واقعی از طریق node-pty روی این دستگاه کار نمی‌کند.

## ساختار پروژه

```
src/
  index.ts         تجزیهٔ آرگومان‌ها و حلقهٔ اصلی
  tree.ts          نمای درختی کتابخانه
  shortcuts.ts     نگاشت میان‌برها و پنل راهنما
  recent.ts        فایل‌های اخیر
  keypress.ts      خوانندهٔ تک‌کلید
  scan.ts          پیمایش بازگشتی، محدودیت عمق
  filters.ts       تجزیه و فیلتر حجم
  random.ts        مولد بدون سوگیری و انتخاب یکتا
  fuzzy.ts         تطبیق زیررشته‌ای با امتیازدهی
  search-select.ts فهرست جست‌وجوپذیر
  picker.ts        منوی رسانه، انتخاب درایو، مرورگر پوشه
  player.ts        تشخیص انجمن فایل در ویندوز
  history.ts       تاریخچهٔ تماشا
  config.ts        مسیرها و تنظیمات
  extensions.ts    جدول قالب‌ها برای هر حالت
  ui.ts            رنگ و قالب‌بندی
```

> توجه: `ts` در فهرست ویدیو هست، بنابراین اگر حالت ویدیو را روی یک پوشهٔ کد منبع بگیرید، فایل‌های TypeScript هم به‌عنوان ویدیو پیشنهاد می‌شوند.

## نکات

- پوشهٔ تأییدشده در `%APPDATA%\rndvid\settings.json` ذخیره می‌شود و نقطهٔ شروع مرورگر در اجرای بعدی است.
- پیوندهای نمادین (symlink) با مسیر واقعی دنبال می‌شوند، پس یک پیوند حلقوی باعث بی‌نهایت شدن اسکن نمی‌شود.
- متغیر محیطی `RNDVID_DATA_DIR` مسیر تنظیمات و تاریخچه را تغییر می‌دهد.
